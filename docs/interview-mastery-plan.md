# AI 零售数据问答助手：项目掌握与面试训练计划

目标不是背诵项目介绍，而是达到三个标准：

1. 讲得出：能用自己的话解释问题、方案、取舍和结果。
2. 写得出：能手写核心 SQL，并读懂关键 Python 代码。
3. 改得动：面对一个新需求，能判断应该修改哪个文件并完成验证。

## 项目全链路

```text
公开零售 CSV
-> Pandas 读取和字段处理
-> SQLite 建库：fact_sales + dim_product
-> 用户输入业务问题
-> Prompt 注入表结构、指标口径和中文枚举
-> 大模型生成 SQL
-> 清理 Markdown 围栏
-> 危险意图与只读 SQL 校验
-> SQLite 只读连接执行查询
-> Pandas DataFrame
-> 表格、图表和业务解释
-> 黄金问题评测、Bad Case、单元测试
```

## 第一阶段：业务问题与数据模型

### 必须理解

- 目标用户为什么不直接写 SQL。
- Text-to-SQL 解决了什么，又没有解决什么。
- `fact_sales` 和 `dim_product` 分别保存什么。
- 为什么商品信息适合拆成维度表。
- 为什么用户分层和地区暂时保留在事实表。

### 动手验收

- 画出两张表及其关联键。
- 不看文档，解释五个核心指标口径。
- 手写三条基础 SQL：整体销售额、品类销售额排行、VIP 客单价。

## 第二阶段：SQL 与数据分析能力

### 必须理解

- `WHERE`、`GROUP BY`、`JOIN`、`ORDER BY`、CTE 和时间聚合。
- 净销售额、订单数、客单价、平均折扣的区别。
- SQL 能执行不代表业务答案正确。

### 动手验收

- 独立完成 10 道逐级 SQL 题。
- 每道题先写指标口径，再写 SQL，再用结果核对。
- 面试官改变筛选条件时，能在 5 分钟内修改查询。

## 第三阶段：程序调用链

### 必须理解

- `app.py` 如何组织页面和一次查询。
- `src/prompts.py` 为什么必须显式提供表结构和口径。
- `src/llm.py` 如何调用兼容 OpenAI 接口。
- `src/db.py` 如何建库和返回 DataFrame。

### 动手验收

- 根据函数名复述一次请求经过哪些文件。
- 给“增加地区筛选”需求定位修改位置。
- 关闭代码后，画出完整调用链。

## 第四阶段：安全与可靠性

### 必须理解

- Prompt 中要求只读不是可靠的安全边界。
- 输入危险意图、输出 SQL 校验、SQLite 只读连接分别解决什么问题。
- 查询中断、输入长度和结果行数限制防什么风险。
- 当前关键词校验仍然不是生产级 SQL 安全方案。

### 动手验收

- 解释 `SELECT`、只读 `WITH`、多语句注入的处理结果。
- 新增一个安全回归测试。
- 能说明为什么生产环境还需要 SQL AST、权限和审计。

## 第五阶段：评测与 Bad Case

### 必须理解

- SQL 执行成功率和答案正确率为什么要分开。
- 黄金问题、标准答案和容差分别是什么。
- 当前 15 条预设题的 100% 不能泛化到开放问题。
- 当前答案检查器只搜索展开后的值，未严格验证列、行和对应关系，可能误判。

### 动手验收

- 找出评测代码的一个可信度问题。
- 将开发题与未见测试题分开。
- 为列名、行对应关系和排序增加严格检查与测试。

## 第六阶段：部署故障与模拟面试

### 必须理解

- 云端冷启动为什么会出现数据库文件存在但表尚未就绪。
- 临时数据库完整构建后原子替换为什么能修复竞态。
- 单元测试如何防止问题再次出现。

### 最终验收

- 90 秒项目介绍。
- 15 分钟技术与产品追问。
- 现场手写一条 SQL。
- 现场完成一个小需求并运行测试。
- 坦诚说明 AI 辅助范围，以及自己如何验证代码和结果。

## 建议节奏

每天 1.5 到 2 小时，连续 7 天：

| 天数 | 内容 | 当天产出 |
| --- | --- | --- |
| 第 1 天 | 业务问题、数据表、指标 | 项目图 + 3 条 SQL |
| 第 2 天 | JOIN、分组、时间分析 | 5 条进阶 SQL |
| 第 3 天 | Python 与完整调用链 | 手绘调用链 + 文件定位题 |
| 第 4 天 | Prompt、安全校验 | 1 个安全测试 |
| 第 5 天 | 评测与 Bad Case | 找出并修复 1 个评测缺陷 |
| 第 6 天 | 云端故障、测试、Git | 故障复盘 + 测试演示 |
| 第 7 天 | 模拟面试和现场改需求 | 最终验收记录 |

## 使用 AI 的面试表述原则

可以说使用 AI 辅助生成初版代码、查询资料和排查问题，但必须同时说明：

- 业务指标和数据模型由自己核对；
- 关键 SQL 用数据库结果复核；
- 安全规则和评测结果有自动化测试；
- 对 AI 生成但自己无法解释的代码不写入简历成果。

项目所有权不取决于是否使用 AI，而取决于能否解释、验证、修改和承担结果。
