# AI 零售经营分析助手 V2 PRD

版本：V2.1

更新日期：2026-07-13

## 1. 背景

V1 已跑通自然语言生成 SQL、只读校验、数据查询、图表、业务解释和离线评测，但 3 名真实体验用户提出了三个核心问题：主动查数的使用价值不足、页面和结果缺少分析引导、固定数据源无法说明扩展性。

V2 不继续增加更多查询示例，而是调整产品入口、结果层级和数据配置方式。第二轮体验后，V2.1 进一步解决问题前提校验、多系列图表和字段适配问题。

## 2. 目标用户

第一目标用户：没有专职数据分析支持，需要自己查询销售数据的运营、产品和业务人员。

第二目标用户：希望快速查看经营重点的小团队负责人。

非目标用户：已经拥有成熟 BI、专职数据团队、复杂权限和实时数仓的大型企业。

## 3. 产品定位

> 将零售交易数据整理成可直接阅读的经营简报，并支持业务人员通过自然语言继续查询和追问。

## 4. V2 功能

### 4.1 经营简报

用户无需输入问题即可看到累计净销售额、订单数、客单价、最新月份变化、领先渠道和下降明显的品类。

所有数字由 SQL 计算，不让大模型直接生成经营指标。

### 4.2 自然语言分析

保留 Text-to-SQL 主链路。查询结果按以下顺序展示：

1. 直接回答问题的结论。
2. 关键指标。
3. 与问题匹配的图表。
4. 三个推荐追问。
5. 折叠的数据明细、SQL 和安全状态。

### 4.3 推荐追问

根据当前问题和返回字段，通过确定性规则生成三个追问。第一版不额外调用模型，降低成本并方便测试。

### 4.4 可配置语义模型

使用 `config/semantic_model.json` 管理：

1. 表和字段说明。
2. 表关联关系。
3. 指标口径。
4. 字段约束。
5. 中文业务词映射。
6. 数据能力边界。
7. SQL 生成规则。

`src/semantic_model.py` 负责读取、校验并生成 Prompt 上下文。

### 4.5 会话级临时数据源

用户可以上传单张销售明细 CSV。系统识别订单号、日期、品类、渠道、销售额、单价等常见中英文字段别名，补全可选字段，再校验日期和数字类型并为当前会话生成独立 SQLite 文件。

上传数据不能覆盖公共 `data/app.db`，恢复演示数据后删除当前会话临时库。

### 4.6 诊断问题与可信结论

1. 对“为什么某渠道最差”先统一渠道口径并校验前提。
2. 前提成立时拆解订单数和客单价；前提不成立时直接纠正。
3. 只有销售明细时不声称发现流量、活动、库存等因果原因。
4. 排名、趋势、峰值和变化率由查询结果确定性计算，不交给模型自由复述。

### 4.7 图表规则

1. 时间加渠道或品类时按第二维度绘制多条折线，不把不同系列串成一条线。
2. 月份、渠道、品类和金额单位中文化。
3. 单个汇总值不绘制粗大的单柱，柱形图保留合理间距。

## 5. 安全与边界

1. 继续保留危险意图拦截、只读 SQL 校验、SQLite `query_only` 和查询中断。
2. 上传文件限制为 CSV、20 MB 和 250,000 行。
3. V2.1 支持常见字段别名，但只接收单张销售明细，不宣称自动理解任意多表或企业数据库。
4. 不支持库存、成本、利润、退货、评价、实时数据和企业权限。
5. 经营简报只能指出数据变化和分析线索，不能虚构因果原因。

## 6. 验收标准

1. 打开页面无需提问即可看到经营简报。
2. 查询结果优先展示结论和图表，数据与 SQL 可折叠查看。
3. 每次正常查询出现三个可点击追问。
4. 修改语义 JSON 后，Prompt 上下文随之变化。
5. 常见中英文字段能自动映射，缺少核心字段时给出明确提示。
6. 适配后的 CSV 可以生成隔离的临时数据库并完成查询。
7. 上传数据不会修改公共演示库。
8. 新旧单元测试全部通过。
9. “为什么线上最差”能先校验前提并说明因果边界。
10. 多渠道月度趋势显示为独立折线，中文月份、图例和金额单位正确。
11. 原来的 3 名体验用户完成 V2.1 复测；在此之前不能宣称用户认可。

## 7. 第二轮测试任务

1. 不提问，在两分钟内说出最新月份最值得关注的变化。
2. 查询销售额最高的品类，并通过推荐追问继续分析渠道表现。
3. 找到这次查询的数据和 SQL 依据。
4. 上传一份使用常见中文字段名的销售明细，并确认字段映射和经营简报发生变化。

记录任务完成情况、耗时、提示次数、是否点击追问、是否查看原始表和继续使用意愿。
