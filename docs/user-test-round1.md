# 第一轮真实用户体验记录

记录日期：2026-07-13

测试版本：V1，AI 零售数据问答助手

测试人数：3 名体验用户

说明：本记录来自真实体验反馈，但样本量只有 3 人，也未证明他们能代表完整目标市场。本文只用于发现问题和确定下一轮迭代，不将其包装成正式市场调研。

## 用户原话

U1：

> 感觉没什么用，图个新鲜，问手下不就好了。

U2：

> 画面好丑，没有用下去的欲望，也没有帮我扩展，只有数据我自己打开表看不就好了，还能摸摸鱼。

U3：

> 还可以，但是公司新的数据怎么办，未来接入更庞大更复杂的数据怎么办，还能用吗？

## 问题归类

### 1. 使用价值

第一版默认“不会 SQL 的管理者会主动输入问题”，但管理者可能已有下属、固定报表和沟通方式。自然语言查数本身不足以改变原有习惯。

产品需要区分两类入口：负责人需要打开页面就能看到经营重点；缺少数据支持的运营和业务人员才更需要自助查询。

### 2. 分析体验

第一版主要返回表格、图表和一段解释，仍然要求用户自己判断哪里重要、下一步问什么。它降低了 SQL 门槛，却没有明显降低分析门槛。

页面视觉层级也不足，数据明细和技术信息占据主要位置，影响继续使用的意愿。

### 3. 数据扩展性

第一版表结构、指标口径和业务词映射主要写在 Prompt 代码中，数据来源固定为一份 CSV。它能证明核心链路可运行，但不能证明可以直接接入任意企业数据。

## V2 决策

决定做：

1. 页面增加无需提问的经营简报和“值得关注”信息。
2. 查询结果先展示结论、指标、图表和推荐追问，再折叠展示数据与 SQL。
3. 表、字段、指标、关联、业务词和能力边界拆成独立语义配置。
4. 支持同结构 CSV 校验，并为当前会话生成隔离的临时数据库。
5. 改版后邀请原来的 3 名用户完成固定任务复测。

暂时不做：

1. 任意数据库自动接入。
2. 登录、企业权限、审计和实时数仓。
3. 自动预测和因果分析。
4. 复杂拖拽式 BI 仪表盘。

原因：本轮优先验证“是否比直接看表更快获得结论”和“换同结构新数据是否仍能工作”，不把求职项目扩张成无法完成的企业平台。

## 第二轮待验证假设

1. 用户能否不输入问题就找到最新经营变化。
2. 用户是否愿意点击推荐追问继续分析。
3. 用户是否能找到数据与 SQL 依据并理解结果来源。
4. 用户能否上传同结构新数据并看到页面更新。
5. 用户是否仍认为直接看 Excel 或询问别人更方便。
