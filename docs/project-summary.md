# AI 零售数据问答助手项目说明

## 项目背景

产品、运营或业务同学在分析销售数据时，经常需要回答“哪个品类销售额最高”“不同渠道表现如何”“某个月销售趋势怎样”这类问题。传统方式通常需要会写 SQL，或者反复找数据同学取数，沟通成本较高。

本项目选择零售销售数据作为场景，尝试用大模型把自然语言问题转换为 SQL，再查询本地数据库并展示结果。项目定位是一个本地 AI 数据产品原型，重点验证从业务问题、数据建模、SQL 生成、结果展示到评测记录的完整流程。

## 用户需求

目标用户是需要快速查询业务数据、但不一定熟悉 SQL 的产品、运营和业务分析人员。

核心需求包括：

1. 用自然语言提出销售数据问题，减少手写 SQL 的门槛。
2. 查询结果要能看懂，不只返回 SQL，还要展示表格、图表和简短解释。
3. 指标口径要清楚，例如 GMV、订单数、客单价、销售件数、平均折扣。
4. 查询过程要安全，不能因为用户输入或模型输出导致删除、修改数据库。
5. 结果需要可评测，能够记录成功、失败和问题原因，方便继续优化。

## 产品方案

项目采用 Streamlit 搭建本地网页原型，使用 SQLite 存储销售数据，使用 OpenAI-compatible API 生成 SQL。

产品流程为：

1. 用户在页面输入业务问题。
2. 系统把表结构、字段说明和指标口径拼接到 Prompt 中。
3. 大模型根据问题生成 SQLite SQL。
4. 系统先做安全校验，只允许只读查询。
5. SQL 通过后查询 SQLite 数据库。
6. 页面展示生成的 SQL、查询结果、可视化图表和中文业务解释。
7. 评测脚本记录问题、生成 SQL、执行状态、错误类型和 Bad Case。

第一版不做登录权限、云端部署、生产数据库连接和复杂 BI 仪表盘，重点先验证核心链路是否能跑通。

## 落地过程

1. 数据准备：整理公开零售销售数据，生成 120,000 行销售明细数据。
2. 数据建模：将原始销售宽表整理为 `fact_sales` 销售事实表和 `dim_product` 商品维度表。
3. 指标梳理：定义 GMV、订单数、客单价、销售件数、平均折扣等常用指标口径。
4. Prompt 设计：把表结构、字段约束、指标口径和 SQL 输出规则写入提示词。
5. 页面实现：完成问题输入、示例问题、SQL 展示、查询结果、图表和业务解释。
6. 安全校验：限制 SQL 为只读查询，拦截删除、修改、建表、多语句注入等风险。
7. 评测记录：整理 20 条测试问题，自动生成 `results.csv`、`bad_cases.csv` 和评测报告。
8. 文档整理：补充 README、PRD、数据字典、Prompt 记录、安全清单和运行截图。

## 复盘总结

项目已经跑通自然语言问数、SQL 生成、安全校验、数据库查询、结果展示和评测记录的闭环。当前 20 条评测问题中，SQL 执行成功 18 条，执行成功率为 90.00%。

项目中发现的典型问题包括：

1. 模型有时会生成不符合当前安全规则的 SQL 写法，需要继续优化安全校验和 Prompt 约束。
2. 部分问题即使能执行，也需要人工复核答案是否真正符合业务口径。
3. 当前项目是本地原型，还没有部署到线上环境，也没有接入真实企业数据库。

后续可以继续优化：

1. 将评测问题扩展到 40 条以上，覆盖更多指标和组合筛选场景。
2. 增加人工标注的标准答案，用于判断结果是否正确。
3. 优化页面交互，例如增加历史记录、常用问题模板和导出功能。
4. 尝试部署到 Streamlit Cloud 或内网环境，方便他人访问演示。

面试时可以这样概括：这是一个本地 AI 数据产品原型，重点不是上线，而是完整跑通从业务问题、数据处理、Prompt 设计、SQL 安全校验到评测复盘的流程。
